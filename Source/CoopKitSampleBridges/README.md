# CoopKit sample bridges

The sample project's framework (module `CoopPlugins`: game mode, game state, player state, player controller, character) does not depend on any CoopKit plugin. This module, `CoopKitSampleBridges`, is the only code that links against the plugins: each bridge is one link between the sample and a plugin, or between two plugins. Remove a plugin from the project and you remove its bridges with it; nothing else changes.

Some plugins join the sample through content only, with no bridge: a Blueprint subclass of a framework class carrying the plugin's component, plus the plugin's data assets.

| Revive | `Private/CKSampleReviveBridge.h/.cpp` | Sample <-> CoopKit Revive | World subsystem. On the maps in `ReviveMaps`, the server adds the Revive match component to `ACKSampleGameState`; the match component then gives every player, controller and pawn their Revive components. Clients get no keys: in a co-op game the host saves. Nothing else is needed: CoopKit Save saves the game state, every player state and every player's pawn with its position by itself. | Matchmaking -> Sessions | `Private/CKSampleMatchmakingSessionsBridge.h/.cpp` | CoopKit Matchmaking -> CoopKit Sessions | Game instance subsystem. ## Sessions UI: calls and the matching Blueprint nodes

The session screens call only what a Blueprint graph can call. To rebuild them in Blueprint, use these nodes (category *CoopKit|Sessions*):

| Screen action | C++ call in the bridge | Blueprint node |
|---|---|---|
| Host | `UCKSessionsSubsystem::HostSession(nullptr, HostMap)` + `OnHostComplete` | **Host Session** (async: *On Success* / *On Failure*) |
| Find sessions | `UCKSessionsSubsystem::FindSessions(nullptr)` + `OnFindComplete` | **Find Sessions** (async) |
| Session row | `UCKSessionsLibrary::GetHostName`, `GetPlayerCounts`, `GetPingMs`, `IsMatchInProgress` | the same library functions |
| Join (click a row) | `UCKSessionsSubsystem::JoinSession(Result)` + `OnJoinComplete` | **Join Session** (async) |
| Status after a lost session | `UCKSessionsSubsystem::GetLastFailure` | **Get Last Failure** |
| Players and ready flags | game state's player array, `UCKSessionsPlayerComponent::FindPlayerComponent`, `IsReady`, `OnReadyChanged` | **Find Player Component**, **Is Ready**, **On Ready Changed** |
| Ready | `UCKSessionsPlayerComponent::SetReady` on the local player's component | **Set Ready** |
| Phase and countdown | `UCKSessionsLobbyComponent::FindLobbyComponent`, `GetPhase`, `GetCountdownSecondsLeft`, `GetPlayerCount`, `GetReadyPlayerCount`, `OnPhaseChanged` | **Find Lobby Component**, **Get Phase**, **Get Countdown Seconds Left**, **On Phase Changed** |
| Start the match (host) | `UCKSessionsLobbyComponent::StartMatchNow` | **Start Match Now** |
| Leave | `UCKSessionsSubsystem::LeaveSession` | **Leave Session** |

The async nodes wrap the subsystem's functions and events; C++ in another module calls the subsystem directly.
